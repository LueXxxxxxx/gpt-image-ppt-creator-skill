# GPT Image 纯图像 PPT 工作流

本 skill 用于生成纯图像 PPT。每一页 PPT 只放置一张由 GPT Image 生成的整页图片，不创建可编辑文本框、图表或形状图层，除非用户明确要求改变这一点。

## 必须遵守的确认节点

不要跳过以下确认：

1. 在生成 PPT 大纲前，先和用户确认需要哪些页面定位类型。
   - 常见页面定位包括：封面页、目录页、过渡页/章节页、内容页、总结页、尾页/结束页。
   - 如果用户已经明确指定页面类型，复述选择后继续。
   - 如果用户不确定，推荐最小完整结构：封面页、目录页、内容页、尾页。
2. 页面定位确认后，再生成 PPT 大纲。
3. 大纲生成后，必须让用户确认或修改。
4. 大纲确认后，再提出 2-4 个视觉风格方向。
5. 用户确认一个风格后，再生成风格确认页。
6. 风格确认页是一张 16:9 图片，包含 4-6 页 PPT 缩略预览。
7. 用户确认风格确认页后，再开始逐页生成最终图片。

## 页面定位

使用以下页面定位：

- `cover`：封面页
- `agenda`：目录页
- `transition`：过渡页/章节页
- `content`：内容页
- `summary`：总结页
- `closing`：尾页/结束页

向中文用户展示大纲时，使用中文页面定位名称。结构化 manifest 中仍使用英文 role 值。

## 页面定位选择逻辑

生成大纲前，先询问用户需要哪些页面定位类型。

如果用户不确定：

- 推荐保留：封面页、目录页、内容页、尾页。
- 仅当 PPT 有清晰章节，并且用户希望有章节切换感时，加入过渡页。
- 当 PPT 属于学术答辩、商务汇报、研究报告、方案汇报、复盘总结、决策汇报时，建议加入总结页。

生成大纲时，再判断过渡页是否必要：

- 如果每个内容页主标题只对应一页内容，询问用户是否去掉过渡页。
- 如果整体 PPT 模块数大于等于三部分，询问用户是否去掉过渡页，以减少页数和重复感。
- 如果两个条件同时满足，除非用户需要正式章节式汇报，否则应明确建议去掉过渡页。

## 大纲要求

每页大纲至少包含：

- 第几页
- 页面定位
- 所属章节/模块
- 主标题
- 次标题
- 正文要点
- 结论/关键 takeaway
- 视觉意图
- 信息密度

生成具体页列表前，必须先确定并记录内容页标题模式 `content_title_mode`：

- 默认值：`topic-only`。内容页 `main_title` 使用不带模块序号的具体内容标题。
- 用户要求时：`module-plus-topic`。内容页 `main_title` 使用“模块序号 + 模块标题”，`subtitle` 使用具体内容标题。

除非用户明确要求混用，否则整份 PPT 的所有内容页必须使用同一种 `content_title_mode`。

生成大纲时应先列出模块，再为每个模块生成页面：

1. 如果保留过渡页，每个模块先生成一页 `transition`，标题为模块标题。
2. 再生成该模块下的 `content` 页。
3. 在默认 `topic-only` 模式下，内容页 `main_title` 必须是具体内容标题，不能等于模块标题。
4. 在 `module-plus-topic` 模式下，内容页 `main_title` 可以等于模块标题，但 `subtitle` 必须是具体内容标题。
5. 大纲展示给用户确认前，应自检是否存在 `role: content` 且 `main_title == module` 但 `subtitle` 为空的页面；如存在，先修正再展示。

目录页应主要展示后续内容页或内容模块的主标题。目录页、过渡页、内容页中的标题文字和编号要互相对应。

## 信息密度规则

整体信息密度遵循：

内容页 > 目录页 >= 封面页 > 过渡页和尾页

### 封面页

封面页要简洁明了。

- 至多包含主标题、次级补充标题、三级要点性质的短内容。
- 不要把背景、目标、意义、方法等展开成大量文字。
- 不要使用密集段落或过多 bullet。
- 不要在封面页渲染页码、章节编号、装饰性数字角标，例如左上角的 `01`。
- 除非用户明确要求，封面页不应出现可见编号。
- 视觉重点是快速建立主题、语气和汇报对象。

### 目录页

目录页重点展示 PPT 整体结构。

- 优先呈现后续内容页或内容模块的主标题。
- 如需呈现额外文字、次级要点，必须非常简短。
- 目录页图文信息饱满度可以大于或等于封面页、过渡页，但必须明显低于内容页。
- 目录标题、过渡页标题、内容页标题的编号形式要统一。
- 目录页中的各个目录项默认是同级并列关系，标题形式、颜色、字号、容器样式、图标处理、对比度和强调程度应保持接近。
- 不要因为某一项靠近页面下方、位于最后一项、视觉上适合收尾，就自动使用反差色、重点色或更强发光效果。
- 只有当用户明确要求，或大纲中明确标注某一项是“重点”“核心”“主线”“本次重点”“优先关注”时，才可以对该目录项使用强调色或重点样式。
- 如果需要突出当前章节，应只在过渡页或内容页体现；目录页默认不高亮单个章节。

### 过渡页/章节页

过渡页只用于从一个部分切换到下一个部分。

- 仅呈现一个章节/模块标题，例如：`01 建设背景`、`二、方法设计`、`3. 重点实战场景`。
- 过渡页的信息呈现量应略低于目录页和封面页。
- 过渡页信息量必须明显低于内容页，至少减少一半。
- 不同过渡页的版式、布局、标题样式、字体颜色、字号、字体设计、标题位置、编号位置、分割线位置和标题块比例应尽量一致。
- 背景、装饰图片、辅助视觉元素可以根据章节内容变化，但文字信息的格式必须类似。
- 不要让后续过渡页漂移成内容页版式，也不要让某一张过渡页突然改变字体风格或标题排版。

当用户选择保留过渡页时：

- 目录页中的每个模块默认都必须有对应过渡页，除非用户明确确认跳过某个模块。
- 第一张已确认的过渡页就是“过渡页母版”。
- 后续过渡页必须参考这张母版生成；如果图像工具支持图片输入，必须把第一张过渡页作为主要参考图。
- 最近一张已确认过渡页可以作为辅助参考，但不能取代第一张母版。
- 后续过渡页只允许修改：章节编号、章节标题、背景图像、装饰图片、少量辅助元素。
- 后续过渡页不得修改：标题区布局、编号样式、编号位置、标题位置、标题基线、字体设计、字号、字体颜色、发光/描边效果、分割线位置、标题容器形状、标题块比例、主视觉结构、页面留白。
- 如果图像工具不支持图片输入，也要在 prompt 中逐项锁定上述不允许修改的元素。
- 每次生成过渡页后，检查它是否和第一张过渡页母版明显偏离；如偏离，应重新生成该过渡页，而不是继续生成后续页。

### 内容页

内容页承载主要信息。

- 内容页主标题固定在左上角。
- 所有内容页的主标题在位置、样式、字号、颜色处理上尽可能一致，仅文本不同。
- 同一章节或同一主标题下的相近内容模块，模块标题样式要一致。
- 正文排版可以根据大纲内容变化，例如框架图、流程图、对比矩阵、时间线、指标面板、案例卡片、分层结构等。
- 内容页左上角主标题有两种允许模式：
  - 默认模式：不带模块序号，直接使用具体内容标题，例如 `发布流程与数据反馈`、`分镜设计：把剧本翻译成镜头`。
  - 用户要求时的替代模式：沿用“模块序号 + 模块标题”作为主标题，并用次级标题呈现具体内容标题，例如主标题 `05 后期制作与发布优化`，次级标题 `发布流程与数据反馈`。
- 默认使用“不带序号的具体内容标题”模式。
- 只有用户提出统一调整内容页标题层级时，才切换为“模块序号 + 模块标题 + 次级具体标题”模式。
- 内容页的主次标题呈现方式必须整体接近，不要一部分内容页使用模块编号标题，另一部分内容页只使用具体标题，除非用户明确要求混用。
- 如果大纲中某一页 `role: content` 且 `main_title` 与 `module` 完全相同，但没有 `subtitle` 或其他具体内容标题，说明这一页缺少内容页标题层级，应补充具体次级标题，或改为默认模式。

### 总结页

总结页用于提炼重点结论，不应引入大量新信息。

- 适合学术答辩、商务汇报、研究报告、方案复盘等场景。
- 呈现关键结论、建议、启示、决策依据或最终回答。
- 信息密度低于内容页。

### 尾页/结束页

尾页应简洁，接近封面页的克制程度。

- 通常仅呈现：`感谢聆听`、`谢谢观看`、`感谢批评指正` 等。
- 至多呈现本次汇报标题和副标题。
- 不要添加密集总结文字，除非用户明确要求。
- 不要在尾页渲染页码、章节编号或装饰性数字角标，除非用户明确要求。

## 编号一致性

选择一种编号体系，并在目录页、过渡页、内容页中保持统一：

- 中文数字：`一、二、三`
- 阿拉伯数字：`1. 2. 3.`
- 两位数字：`01 02 03`

除非用户要求层级编号，否则不要在同一份 PPT 中混用多种编号体系。

重要：大纲里的 `number` 只是内部排序和文件命名用的元数据，不是页面中要显示的文字。不要把 `number: 1` 渲染成封面页的 `01`。只有目录页、过渡页、内容页标题中已经明确写出的编号，才可以作为可见文字生成。

## 风格确认页

风格确认页是一张 16:9 图片，包含 4-6 个 PPT 缩略页预览。

要求：

- 只展示用户选择保留的页面定位类型。
- 如果用户选择了封面、目录、过渡、内容、总结、尾页，应尽量覆盖其中的代表页面。
- 预览要像同一套 PPT 系统，不要像彼此无关的海报。
- 用户确认风格确认页后，才能逐页生成最终图片。

## 逐页生成规则

最终页面逐页生成，每页是一张完整 16:9 PPT 图片。

如果 PPT 包含过渡页：

- 先生成第一张过渡页，并把它作为过渡页母版确认。
- 在第一张过渡页被接受前，不要继续生成后续过渡页。
- 后续所有过渡页都必须以第一张过渡页母版为主要参考。
- 不要在没有母版参考的情况下批量生成全部过渡页。

每页 prompt 必须包含：

- 已确认的整体风格
- 已确认的风格确认页作为一致性参考
- 内部页序号，仅用于生成进度和文件命名，不作为画面文字
- 页面定位
- 页面信息密度
- 主标题、次标题、正文、结论等需要出现在图片中的准确文本
- 视觉构图要求
- 角色特定约束

必须强调：

- 文字清晰、可读、无错别字。
- 不要添加 prompt 之外的虚构文字。
- 不要把内部页序号、manifest 中的 `number` 字段、文件名编号渲染到页面中。
- 目录页所有目录项默认同级同样式，不要自动高亮最后一项、下方项目或任意单项。
- 内容页左上角主标题位置和样式保持一致，标题层级也要一致。
- 默认情况下，内容页使用不带序号的具体内容标题；如果用户要求沿用模块序号和模块标题，则所有内容页都应统一使用“模块标题 + 次级具体标题”的层级。
- 过渡页只展示章节标题和少量辅助视觉元素，并严格参考前序过渡页的文字格式和版式。
- 封面页和尾页保持留白和克制。

## 中断恢复

长 PPT 逐页生成时容易在 10 页之后中断，必须让流程可续跑。

开始逐页生成前，创建或更新 `generation-state.json`，记录：

- PPT 标题
- 总页数
- 图片输出目录
- 已完成页码
- 失败页码
- 下一页页码

生成过程中：

- 每生成成功一页，就立刻更新 `generation-state.json`。
- 如果用户没有发出新指令但生成中断，自动从第一张缺失图片继续。
- 续跑前检查 `slides/` 目录，已有的非空 `slide-###.png` 视为已完成，不要重复生成。
- 所有图片生成完成后，再打包 PPT。

如果用户在中断期间发出新指令，以用户最新指令为准，不要盲目续跑。

## 原始图片目录优先规则

第一批经用户认可的最终页面图片目录就是打包 PPT 的权威来源，默认是 `slides/`。

必须遵守：

- 当 `slides/` 中的图片已经满足用户要求时，直接基于 `slides/` 打包 PPT。
- 不要默认创建 `slides-final/`、`slides-rendered/`、`slides-processed/` 等二次处理目录。
- 不要在 GPT Image 已经生成可接受页面后，再用 PIL、canvas、HTML 截图或其他本地渲染方式重画文字、遮罩、面板、图层或版式。
- 预览拼图只用于快速核对，不是 PPT 打包来源。
- 如果检查发现文字可读性、遮罩或布局问题，应询问用户是“重新用 GPT Image 生成受影响页面”，还是“直接使用现有 slides/ 图片打包”。
- 不要用本地脚本重绘一版替代原图；这一流程不属于本 skill 的默认能力。
